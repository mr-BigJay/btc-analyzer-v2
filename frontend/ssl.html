اتصال دامنه و گواهی SSL

TLS روی لبه (Nginx) قطع می‌شود. سرویس‌های داخلی فقط در شبکه Docker صحبت می‌کنند.

۱) DNS

در پنل دامنه یک رکورد A بسازید:

example.com     A     IP_SERVER
www.example.com A     IP_SERVER

تا انتشار DNS صبر کنید (dig example.com +short باید IP سرور را نشان دهد).

۲) تنظیم دامنه در پروژه

cd /opt/btc-analyzer-v2
export DOMAIN=example.com
export EMAIL=admin@example.com
# یا داخل .env:
# DOMAIN=example.com
# CERTBOT_EMAIL=admin@example.com

۳) اجرای اسکریپت SSL

اسکریپت آماده در مخزن، Certbot را نصب می‌کند، گواهی Let’s Encrypt می‌گیرد و پیکربندی Nginx را فعال می‌کند:

sudo bash deploy/scripts/setup-ssl.sh
docker compose up -d nginx
curl -I https://example.com

۴) فعال‌سازی دستی (اختیاری)

sudo apt install -y certbot
sudo certbot certonly --standalone -d example.com -d www.example.com --email admin@example.com --agree-tos --non-interactive

# کپی قالب SSL
DOMAIN=example.com
sed "s/__DOMAIN__/${DOMAIN}/g" deploy/nginx-ssl.conf.template > deploy/nginx.conf
docker compose up -d nginx

قبل از گرفتن گواهی با حالت standalone، سرویس‌هایی که پورت ۸۰ را اشغال کرده‌اند موقتاً متوقف شوند یا از روش webroot استفاده کنید. اسکریپت پروژه این ترتیب را مدیریت می‌کند.

۵) تمدید خودکار

sudo crontab -e
# هر روز ساعت ۰۳:۱۵
15 3 * * * certbot renew --quiet && cd /opt/btc-analyzer-v2 && docker compose exec -T nginx nginx -s reload

۶) بررسی نهایی

  • https://دامنه/ — صفحه فارسی
  • https://دامنه/dashboard.html — داشبورد
  • https://دامنه/ready — آمادگی سرویس
  • قفل HTTPS در مرورگر و ریدایرکت HTTP→HTTPS
